# 0.2.1. Markdown 双面板 SCM 与 Git 历史支持探索

## 目标

优化“Markdown 智能双面板锁定”功能，解决以下场景下无法自动 split 或失效的问题：

1. **资源管理器中标记为 A（新增）、M（修改）、U（未追踪）等状态的 `.md` 文件**。
2. **Source Control（版本控制）面板（包括 Changes 变更列表、Git History / Graph 等）中的所有 `.md` 文件**。

同时，认可并采用**开发文档编号与版本号（0.2.x）挂钩**的管理规范，以便清晰追溯每个版本的变更设计。

---

## 问题分析与根因

当前实现的 `markdownDualPane.ts` 在以下两处地方进行了严格限制，导致 SCM 相关的场景被过滤或打断：

### 1. Scheme 过滤限制
在 `isMarkdownFile` 中，我们限制了只有 `file` scheme 的文档才触发双面板：
```typescript
function isMarkdownFile(editor: vscode.TextEditor): boolean {
  return editor.document.languageId === 'markdown' && editor.document.uri.scheme === 'file';
}
```
* **根因**：
  - 当用户在 **Source Control** 面板中点击修改过的 `.md` 文件，或者在 **SCM Graph/History** 中查看历史 commit 中的 `.md` 文件时，VS Code 打开的文档 scheme 通常是 **`git`**（例如 `git:/path/to/file.md?{"ref":"..."}`）或者其他的版本控制 scheme（如 `gitlens` 等）。
  - 因为 scheme 不是 `file`，事件监听直接被 return 过滤，无法触发双栏布局。

### 2. Diff 编辑器的 Tab 类型不匹配
当用户在 SCM 面板双击或点击变更文件时，VS Code 默认会打开一个 **Diff 编辑器**（对比暂存区/上一版本与当前工作区）。
* **根因**：
  - Diff 编辑器在 VS Code 中的 Tab 输入类型是 **`TabInputTextDiff`**，而非常规的 `TabInputText`。
  - 在我们现有的 `isLayoutAlreadyCorrect` 检测中，只判断了 `TabInputText`：
    ```typescript
    const sourceActiveInGroup1 =
      group1.activeTab?.input instanceof vscode.TabInputText
      && group1.activeTab.input.uri.toString() === uriString;
    ```
    对于 Diff 编辑器，这个检测会返回 `false`，导致插件误判为“布局不正确”。
  - 随后，`arrangeMarkdownLayout` 会尝试调用 `showTextDocument` 强行将该文件作为普通文本编辑器打开：
    ```typescript
    await vscode.window.showTextDocument(uri, {
      viewColumn: vscode.ViewColumn.One,
      preserveFocus: false
    });
    ```
    这会**强行把用户的 Diff 编辑器替换成普通编辑器**，破坏了用户对比变更的上下文，体验很差。

## 优化方案设计

### 1. 扩展支持的 Scheme 列表
除了本地文件的 `file` 协议，内置 Markdown 预览同样支持预览 `git` 等虚拟文档（渲染历史 commit 中的 markdown 内容）。我们需要放宽过滤条件：
```typescript
const supportedSchemes = ['file', 'git', 'gitlens', 'vscode-local-history', 'review'];

function isMarkdownFile(editor: vscode.TextEditor): boolean {
  return editor.document.languageId === 'markdown'
    && supportedSchemes.includes(editor.document.uri.scheme);
}
```

### 2. 兼容 Diff 编辑器 (TabInputTextDiff)
在判断“布局是否已正确”时，需同时兼容 `TabInputText` 和 `TabInputTextDiff`：
* 如果是普通编辑器：比对 `tab.input.uri` 是否与当前 `uri` 一致。
* 如果是 Diff 编辑器：比对 `tab.input.modified`（修改后的文件 URI）是否与当前 `uri` 一致。

```typescript
function isSourceTab(tab: vscode.Tab | undefined, uri: vscode.Uri): boolean {
  if (!tab) return false;
  const uriString = uri.toString();

  // 普通文本编辑器
  if (tab.input instanceof vscode.TabInputText) {
    return tab.input.uri.toString() === uriString;
  }

  // Diff 编辑器 (对比视图)
  if (tab.input instanceof vscode.TabInputTextDiff) {
    return tab.input.modified.toString() === uriString;
  }

  return false;
}
```

### 3. 避免破坏/替换 Diff 视图
在 `arrangeMarkdownLayout` 调整布局时：
* 如果 Group 1 中当前活跃的 Tab **已经**是该文件的 Source Tab（不论是 Diff 编辑器还是普通文本编辑器），**不要**再次调用 `showTextDocument`（避免将 Diff 编辑器冲掉）。
* 只有当 Group 1 中活跃的不是该文件时，才调用 `showTextDocument` 打开。

```typescript
// 调整前检测：如果 Group 1 中该文件的编辑器已经处于活跃状态，我们就无需强行 showTextDocument
const isSourceActiveInGroup1 = isSourceTab(group1.activeTab, uri);

if (!isSourceActiveInGroup1) {
  await vscode.window.showTextDocument(uri, {
    viewColumn: vscode.ViewColumn.One,
    preserveFocus: false
  });
}
```

## 预估变更代码 (src/markdownDualPane.ts)

修改 `isLayoutAlreadyCorrect`、`arrangeMarkdownLayout` 和辅助判定方法：

```typescript
// 支持的协议
const supportedSchemes = ['file', 'git', 'gitlens', 'vscode-local-history', 'review'];

function isMarkdownFile(editor: vscode.TextEditor): boolean {
  return editor.document.languageId === 'markdown'
    && supportedSchemes.includes(editor.document.uri.scheme);
}

function isSourceTab(tab: vscode.Tab | undefined, uri: vscode.Uri): boolean {
  if (!tab) return false;
  const uriString = uri.toString();
  if (tab.input instanceof vscode.TabInputText) {
    return tab.input.uri.toString() === uriString;
  }
  if (tab.input instanceof vscode.TabInputTextDiff) {
    return tab.input.modified.toString() === uriString;
  }
  return false;
}

// 在 arrangeMarkdownLayout 中：
async function arrangeMarkdownLayout(uri: vscode.Uri): Promise<void> {
  if (isLayoutAlreadyCorrect(uri)) {
    return;
  }

  const groups = vscode.window.tabGroups.all;
  const group1 = groups.find(g => g.viewColumn === vscode.ViewColumn.One);

  // 1. 只有当 Group 1 当前活跃的不是该文件的 Source 时，才在 Group 1 打开/聚焦它
  if (!group1 || !isSourceTab(group1.activeTab, uri)) {
    await vscode.window.showTextDocument(uri, {
      viewColumn: vscode.ViewColumn.One,
      preserveFocus: false
    });
  }

  // 2. 确保 Preview 在 Group 2 开启
  if (!findPreviewInGroup(uri, vscode.ViewColumn.Two)) {
    await vscode.commands.executeCommand(
      'vscode.openWith',
      uri,
      markdownPreviewViewType,
      { viewColumn: vscode.ViewColumn.Two, preview: true }
    );
  }

  // 3. 收尾清理和聚焦
  await closeExtraGroups();
  
  // 重新聚焦 Group 1 的源文件/Diff 视图
  // 注意：如果本来就是 Diff 编辑器，showTextDocument(uri) 可能会导致变为普通编辑器。
  // 我们只有在 Group 1 活跃的不是该 Tab 时才 show。
  const currentGroup1 = vscode.window.tabGroups.all.find(g => g.viewColumn === vscode.ViewColumn.One);
  if (currentGroup1 && !isSourceTab(currentGroup1.activeTab, uri)) {
    await vscode.window.showTextDocument(uri, {
      viewColumn: vscode.ViewColumn.One,
      preserveFocus: false
    });
  }
}
```

## 验证计划

### 1. 手动测试场景
- **A/M/U 文件测试**：在本地修改/新增一些 `.md` 文件，使其在 Explorer 中呈现黄色（M）、绿色（A）或灰色（U）。在 Explorer 中点击它们，验证是否依然能完美触发双栏预览。
- **Source Control 面板测试**：在暂存或更改列表中双击一个 `.md` 文件（进入 Diff 视图），验证是否在 Group 1 保持 Diff 视图，同时在 Group 2 自动拉起该文件的 Preview 预览。
- **Git History/Graph 测试**：点击历史 commit 中的某个 `.md` 文件，验证只读的 `git` 协议文件是否也能在 Group 1 呈现只读代码，Group 2 呈现其历史预览。

### 2. 自动化回归测试
- 运行 `npm test` 验证原有的 QuickLook 功能没有受到 any 影响。
