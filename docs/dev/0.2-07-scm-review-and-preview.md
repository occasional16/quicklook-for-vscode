## 1. 结论与设计

SCM 和 Explorer 中的 Markdown 应共享 `source`、`preview`、`split` 三种视图及同一个工作区上次状态。三种状态表达的是用户当前的阅读或编辑方式，不应因入口变为 SCM 而中断；区别仅在于 SCM 的源码侧可能是原生 Diff 或历史版本，而不是普通源码编辑器。

### 统一的三种视图

| 视图 | 普通 Markdown | SCM Markdown |
| --- | --- |
| `source` | 1 个 Group，显示源码编辑器 | 1 个 Group，显示 VS Code 原生 Diff、历史源码或普通源码 |
| `preview` | 1 个 Group，显示原生 Markdown Preview | 1 个 Group，显示该变更目标版本的原生 Markdown Preview |
| `split` | Group 1 为源码，Group 2 为预览 | Group 1 为原生 Diff、历史源码或普通源码，Group 2 为目标版本预览 |

Diff 内部采用左右比较还是窄窗口下的 inline 模式由 VS Code 决定，不改变外层 Group 计数。`split` 继续遵循 `workbench.editor.openSideBySideDirection` 的 `right` 或 `down`。

普通 Markdown 继续默认关联到原生 Preview；Markdown Diff 则通过 `workbench.diffEditorAssociations` 默认关联到 `default` 文本 Diff。后者优先于普通编辑器关联，使控制器能够从公开的 `TabInputTextDiff` 取得原始侧和修改侧 URI。扩展只提供默认值，用户或工作区的显式关联仍然优先；若用户显式选择渲染式 Markdown Diff，则该自定义 Diff 保持原生行为，不强行纳入三态。

### 继承与切换规则

- 在 Explorer、SCM Changes、Staged Changes 和 SCM History 之间切换 Markdown 时，始终应用工作区记住的上次视图。
- `source` 下点击 SCM 变更，保留原生 Diff；`preview` 下只显示目标版本预览；`split` 下显示原生 Diff 和目标版本预览。
- SCM 的 **Open File** 打开普通工作区文件，但仍继承当前视图；不把“来自 SCM”永久附着到文件状态。
- 若用户关闭 `git.openDiffOnClick`，SCM 点击实际打开普通文件，则直接按普通 Markdown 处理。
- 聚焦 `split` 中任一 Group 不改变状态，也不得导致另一 Group 消失、合并成 Tab 或被错误关闭。
- 使用原生 **Open Preview to the Side** 进入 `split`；关闭源码或 Diff 侧后保留 `preview`，关闭预览侧后保留 `source`，并据此更新上次视图。
- VS Code 当前不为 Diff 提供普通文件的 **Open as Preview**；插件仍需支持继承得到的 `preview` 单面板，并允许用户通过保留预览侧形成该状态。
- 规范布局时继续保护其他 Tab 和未保存内容，不持续纠正用户随后进行的手动布局。

SCM 不再触发此前建议的“临时收拢并记住 `split`”规则；它直接参与统一状态，因此切换 Markdown 文件时不会改变用户当前工作方式。

### Preview 的目标版本

SCM 的 Markdown Preview 必须使用该变更实际代表的目标版本：

| SCM 情况 | 预览目标 |
| --- | --- |
| `Changes` 中的新增、修改或重命名 | 工作区版本 |
| `Untracked` | 工作区文件 |
| `Staged Changes` 中的新增、修改或重命名 | 暂存区版本，不得替换为工作区版本 |
| 同一文件部分暂存 | `Changes` 预览工作区版本；`Staged Changes` 预览暂存区版本 |
| 未暂存删除 | 删除前的暂存区版本 |
| 已暂存删除 | 删除前的 HEAD 版本 |
| SCM History | 当前历史变更的较新侧；删除时使用仍存在的较旧侧 |
| Merge Conflicts | 保留原生 Merge Editor，不套用三态布局 |

原生 Markdown Preview 优先直接读取 Diff 或 History 已提供的 `file:` 或 `git:` URI，不另造内容副本。无法可靠确定目标版本时保留原生编辑器并记录诊断，不得静默预览工作区文件。

### 交互边界

- 非 Markdown 文件不进入 Markdown 状态机。
- 目标版本不可用时不得静默退回工作区文件，因为部分暂存时可能展示错误内容。
- 不读取 Git 扩展私有对象；优先使用 Diff、History 和 VS Code Tab API 已公开的 URI。

### 与 `0.2-06` 的关系

本方案扩展 `0.2-06` 的 Markdown 上次视图设计，并修正其中“Markdown Diff 和 SCM History 不参与状态应用”的边界：可确定目标版本的 Markdown Diff 和 History 参与三态继承；非 Markdown Diff、无法可靠对应目标版本的独立虚拟文档、Untitled、Merge Editor 和其他自定义编辑器仍保持原生行为。

### 以 v0.2.3 为基线的简化审查

`6c39c93` 的永久双面板实现是有价值的最小基线：继续沿用其 debounce、先判断布局、保留 `TabInputTextDiff`、恢复 Group 1 和清理额外 Group 的原则。但它通过“每次激活 Markdown 都强制重建 `split`”换取简单，不能替代当前需要识别用户意图、继承三态和选择正确 Git 版本的状态机。

当前不立即重写控制器。理由不是维护旧代码，而是 SCM 初测已经通过，现阶段没有证据表明结构性重写能在保留全部行为时降低状态数量或事件竞态；此时重写只会扩大回归面。后续仅在出现重复缺陷、同类状态分支继续增加，或能够用更少状态通过同一验收矩阵时再简化，并以现有自动测试和 Extension Host 快照作为不可降低的基线。

## 2. 待确认

无。Merge Editor 具有独立的多侧冲突解决语义，不强行映射为三态；普通 SCM Diff 和 History 则统一继承三态。

## 3. 验收

### 三态继承与布局

- [x] `source` 下切换多个 SCM Markdown，始终为 1 个 Group，并保留各自原生 Diff 或源码。
- [x] `preview` 下切换多个 SCM Markdown，始终为 1 个 Group，并显示各自目标版本的原生预览，不遗留 Diff、空白 Group 或错误版本。
- [x] `split` 下切换多个 SCM Markdown，始终为 2 个有内容的 Group：Group 1 为对应 Diff 或源码，Group 2 为同一目标版本预览。
- [ ] 在 Explorer Markdown、SCM Changes、Staged Changes 和 History 之间往返时连续继承当前视图。
- [x] `split` 中点击或聚焦 Group 1 后 Group 2 不消失、不合并为 Tab；聚焦 Group 2 同样不改变状态。
- [x] `right` 与 `down` 均无 Group 3、空白面板或只剩标题的预览 Group。
- [ ] 原生 **Open Preview to the Side**、关闭任一侧和 **Open File** 按上述规则更新或继承状态。
- [ ] 非 Markdown Diff 和 Merge Editor 不更新上次 Markdown 视图，也不被三态逻辑重排。

### 版本准确性

- [ ] 构造 HEAD、暂存区、工作区内容各不相同的部分暂存文件；两个 SCM 分组的 Preview 分别显示暂存区和工作区内容。
- [ ] 新增、未跟踪、重命名、未暂存删除和已暂存删除均预览规定版本。
- [ ] 删除项使用仍存在的比较侧，且不会错误预览工作区文件。
- [ ] Merge Editor 保持原生布局。
- [ ] 目标版本无法确定时保留原生编辑器并记录诊断，不展示错误 Preview。
