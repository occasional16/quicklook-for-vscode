## 1. 结论与设计

QuickLook 是独立于 Markdown 视图管理的外部预览功能，不参与 `source`、`preview`、`split` 状态，也不改变 VS Code 编辑区布局。

当前 SCM 命令主要取得底层工作区路径。对于部分暂存文件，这会使 `Staged Changes` 错误预览工作区版本；多选时还可能预览并非用户实际触发的第一个条目。因此应单独修正版本选择，而不与 `0.2-07` 的 Markdown 状态机耦合。

### 版本规则

| SCM 情况 | QuickLook 目标 |
| --- | --- |
| `Changes` 中的新增、修改或重命名 | 工作区版本 |
| `Untracked` | 工作区文件 |
| `Staged Changes` 中的新增、修改或重命名 | 暂存区版本 |
| 未暂存删除 | 删除前的暂存区版本 |
| 已暂存删除 | 删除前的 HEAD 版本 |
| SCM History | 用户明确选择或聚焦的历史侧 |
| Diff | 当前明确聚焦的一侧 |

- SCM 的 Working Tree、Index 和 Untracked 分组使用各自的内部命令入口，并由 `scmResourceGroup` 原生上下文决定版本；不从同一路径反推分组。
- Preview 每次优先处理用户实际触发的 `resource`；多选参数只在唯一候选时作为后备，不任意选择列表中的第一个文件。
- 无法可靠确定条目、分组或版本时终止并提示，不静默退回工作区文件。
- Git 快照通过保留原扩展名的临时文件交给 QuickLook，并在文件名中标明 `Staged`、`HEAD`、`History` 或 `Before deletion`。
- Working Tree 和 Untracked 直接使用存在的工作区文件；Working Tree 删除使用暂存区版本。Index 使用暂存区版本，只有该路径在 Index 中不存在时才按“已暂存删除”读取 HEAD，不把其他读取错误当作删除。
- Diff 和 History 编辑器优先使用当前聚焦 TextEditor 的 `file:` 或 `git:` URI；标题或右键命令提供的 URI 只有在不与当前 Diff 两侧冲突时才优先。
- Merge Editor 没有公开、可靠的聚焦侧 URI 契约，保持 VS Code 原生行为；不猜测版本，也不把它纳入本次 QuickLook 版本路由。
- 复用 VS Code 内置 Git 扩展公开的 `getAPI(1)`、Repository 和 `toGitUri`，不读取资源对象的私有状态，也不新增第三方依赖。
