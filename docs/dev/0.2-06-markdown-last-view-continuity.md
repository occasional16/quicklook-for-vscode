# Markdown 上次视图延续工作流

| 字段 | 内容 |
| --- | --- |
| 状态 | Pending Validation |
| 更新 | 2026-08-05 |
| 目标 | 让 Markdown 文件延续用户最后选择的视图，减少插件强制感 |
| 执行授权 | 已授权（2026-08-05：整体替换旧两态实现） |

## 1. 结论与设计

开发者的核心意图是：插件不再预设用户始终想阅读或双面板编辑，而是尊重最近一次明确选择；切换 Markdown 文件时继续当前工作方式。设计还需维持有限空间下清晰、稳定的 1 / 2 Group 布局。

采用三种一等视图取代 `0.2-05` 的强制两态：

| 视图 | 布局 | 含义 |
| --- | --- | --- |
| `source` | 1 Group，仅源码 | 专注编辑 |
| `preview` | 1 Group，仅原生静态预览 | 专注阅读 |
| `split` | 2 Groups，源码加原生动态预览 | 对照编辑 |

### 主要行为

- 用户通过原生 Markdown 操作或关闭一侧形成的视图，成为“上次视图”。仅切换源码/预览焦点不改变视图。
- 切换到另一个普通本地 Markdown 时延续上次视图；切换到非 Markdown 时停止控制，切回后继续延续。
- `preview` 点击 **Reopen as source file** 后进入 `source`，不再自动打开侧边预览。
- `source` 点击 **Open as Preview** 后进入 `preview`；点击 **Open Preview to the Side** 后进入 `split`。
- `split` 中关闭预览后进入 `source`；关闭源码后进入 `preview`。插件不重新打开用户主动关闭的视图。
- `split` 中的 **Open Source File** 只切换焦点，仍保持 `split`。
- 原生命令已经形成完整 `split` 时，插件只记录实际视图并取消过时请求，不再次执行布局命令；聚焦任一 Group 都不得触发布局变化。
- VS Code 1.132 的 Tab API 会将原生动态预览报告为 `mainThreadWebview-markdown.preview`，而其公开 WebviewPanel 类型是 `markdown.preview`；实现必须识别两者。
- `workbench.editorAssociations` 将新文件原生打开为静态预览时，这属于文件切换而非用户改选 `preview`，仍应延续上次视图。
- 默认 `preview` 通过扩展贡献的原生 `*.md → vscode.markdown.preview.editor` 关联直接打开，避免先显示源码再转换的闪烁；显式用户或工作区关联优先。
- 原生关联是静态默认：无闪烁保证适用于默认 `preview`。延续为 `source` 或 `split` 时仍可能发生一次必要转换；插件不为消除该转换而动态改写用户设置。
- `quicklook.markdownViewContinuity.enabled` 默认开启。关闭后停止视图记忆和自动布局，保持当前编辑区不变；重新开启时，以当前已打开的 Markdown 布局作为最近选择。当前没有 Markdown 时继续保留此前工作区记忆。
- 原生 `*.md` Preview 默认关联无法按扩展设置有条件贡献，因此不随此开关变化；需要默认源码的用户可用 `workbench.editorAssociations` 显式覆盖。

### 记忆与初始视图

- 只记住一个工作区级的上次视图，不做逐文件记忆，也不把一个项目的选择带到所有项目。
- 同一工作区重启后延续上次视图；若 VS Code 已恢复出完整的三种视图之一，以实际界面为准。
- 没有历史状态时默认使用 `preview`，优先提供阅读体验。
- 使用 `quicklook.markdownInitialView`（`source` / `preview` / `split`）替换语义已不准确的 `quicklook.markdownOpenMode`；该设置只决定无历史状态时的首次视图。

### 布局边界

- 应用 `source` 或 `preview` 时，整个编辑区恰好 1 个 Group；应用 `split` 时恰好 2 个 Group。
- `split` 继续遵循 `workbench.editor.openSideBySideDirection`：`right` 为左右，`down` 为上下，并确保 Group 2 有正常内容区。
- 规范布局时保留其他 Tab 和未保存内容，不以关闭资产换取 1 / 2 Group。
- 只在视图切换和 Markdown 文件切换时规范布局，不持续巡逻。用户手动形成非规范布局后，插件不立即反向纠正。
- Diff、SCM 历史、虚拟资源、Untitled 和其他自定义编辑器保持 VS Code 原生行为，也不更新上次视图。

### 与 `0.2-05` 的关系

本方案已取代 `0.2-05` 的两态决策，但继续复用 VS Code 原生交互、`right` / `down` 支持和特殊资源边界。最低版本以实际功能依赖为准，不能跟随开发机版本任意上调；当前基线为首次提供所需 Markdown 源码/预览切换操作的 VS Code 1.119。实现已整体替换旧状态逻辑，未叠加兼容分支。

## 3. 验收

### 核心行为

- [ ] `source`、`preview`、`split` 均能稳定存在，不会被自动改成另一种视图。
- [ ] 三种视图下切换到另一普通本地 Markdown，目标文件分别保持同一种视图。
- [ ] 启用或不启用原生 `*.md → vscode.markdown.preview.editor` 关联时，`split` 切换文件都保持 `split`。
- [ ] **Reopen as source file** 只进入 `source`；**Open Source File** 在 `split` 中只切换焦点。
- [x] 在 `split` 中点击 Group 1 只改变焦点，布局和上次视图仍为 `split`（VS Code 1.132 Extension Host，`right` / `down` 均通过）。
- [ ] `split` 中关闭预览后保持 `source`，关闭源码后保持 `preview`，插件不恢复已关闭一侧。
- [ ] 关闭整个 Markdown 会话不会被误判为新的视图选择。

### 布局与边界

- [ ] `source` / `preview` 始终为 1 Group，`split` 始终为 2 Groups。
- [ ] `right` 与 `down` 均无 Group 3、空白预览或被压缩到只剩标题的 Group 2。
- [ ] 切换非 Markdown、Diff、SCM 历史、虚拟资源和 Untitled 时不自动重排。
- [ ] 手动形成非规范布局后插件不立即争夺控制权。
- [ ] 其他 Tab、未保存内容和特殊编辑器不丢失。

### 状态与稳定性

- [ ] 重启同一工作区后延续上次视图；打开其他工作区时不继承。
- [ ] 快速切换多个 Markdown 时只应用最后一个请求，无重复预览或焦点跳动；默认 `preview` 不闪现源码，`source` / `split` 的必要单次转换不留下空白或错误布局。
- [ ] 无历史状态且初始值为 `preview` 时直接出现原生预览，不先闪现源码。
- [ ] 关闭视图延续后，切换 Markdown、切换原生视图和改变拆分方向都不触发记忆或自动布局，当前布局保持不变。
- [ ] 重新开启后，当前 `source`、`preview` 或完整 `split` 成为最近视图；无 Markdown 打开时保留此前工作区记忆。
- [x] **Reopen as source file** 不受 Tab / TextEditor 事件先后顺序影响，不会立即回到预览。
- [x] 新文件原生 Preview 产生重复事件时只执行一次继承，不覆盖已记住的 `source` / `split`。
- [x] 真实 Extension Host 集成测试识别 `mainThreadWebview-markdown.preview`，聚焦 Group 1 后两个 Group 均保留。
- [x] `npm test` 通过（39 / 39）。
- [ ] 在最低支持版本 VS Code 1.119 和当前稳定版 Extension Development Host 中依次人工验证开关、三种视图、文件切换、重启及 `right` / `down`。
