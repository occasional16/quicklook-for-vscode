# 0.2.2. Markdown 双面板焦点保持优化探索

## 目标

解决“Markdown 智能双面板锁定”生效后，活动编辑器的打开和预览重组会夺走键盘焦点，导致：
1. 在资源管理器（Explorer）或 SCM 面板中单击 `.md` 文件后，资源管理器/SCM 失去焦点，用户无法再通过方向键上下切换文件，也无法直接按 `Delete` 删除文件。
2. 用户的键盘焦点被强行转移到编辑器区域（通常是右侧的 Markdown 预览 Webview），严重打断连续操作的体验。

---

## 问题分析与根因

在 VS Code 的原生行为中：
- 当用户在资源管理器中**单击**一个文件时，VS Code 会在编辑器区域以“预览模式（斜体 Tab）”打开该文件，但**键盘焦点仍然保持在资源管理器中**，以便用户使用方向键移动或按快捷键操作。
- 如果用户**双击**或按 `Enter`，焦点才会转移到编辑器中。

而在我们当前的插件实现中，当监听到活动编辑器变为 `.md` 文件时，执行了以下重组逻辑：

```typescript
// 1. 在 Group 1 打开源文件（若未处于活跃状态）
await vscode.window.showTextDocument(uri, {
  viewColumn: vscode.ViewColumn.One,
  preserveFocus: false // 👈 此处为 false，强制将焦点移到 Group 1 编辑器！
});

// 2. 调用命令在 Group 2 打开内置预览
await vscode.commands.executeCommand(
  'vscode.openWith',
  uri,
  markdownPreviewViewType,
  { viewColumn: vscode.ViewColumn.Two, preview: true } // 👈 未设置 preserveFocus，默认会使焦点被右侧 Preview Webview 夺走！
);
```

### 根因总结
1. `vscode.commands.executeCommand('vscode.openWith', ...)` 默认在右侧 Group 2 打开 Preview 视图时，会将焦点强行拉到该 Webview。
2. 即使我们在最后尝试重新聚焦 Group 1 的源文件，调用的也是 `showTextDocument(..., { preserveFocus: false })`，这会将键盘焦点强行锁定在 Group 1 的代码编辑器上。
3. 无论哪种情况，**原本处于资源管理器（Explorer）或 SCM 树形列表上的焦点都会被强行夺走**，导致方向键选择和删除文件功能失效。

---

## 优化方案设计

为了让插件的自动双栏布局在后台无感完成，并且**不干扰用户当前的焦点状态**（如果焦点在资源管理器就留在资源管理器；如果焦点已经在编辑器就留在编辑器），我们需要全面采用 **`preserveFocus: true`** 参数。

### 1. 开启预览时保持焦点
VS Code 的 `vscode.openWith` 命令接受的配置对象中支持传入 `preserveFocus` 参数。将其设为 `true`：
```typescript
await vscode.commands.executeCommand(
  'vscode.openWith',
  uri,
  markdownPreviewViewType,
  {
    viewColumn: vscode.ViewColumn.Two,
    preview: true,
    preserveFocus: true // 👈 保持焦点，防止预览 Webview 夺走焦点
  }
);
```

### 2. 确保源文件显示时保持焦点
在我们调用 `showTextDocument` 确保源文件（或 Diff 编辑器）在 Group 1 呈现时，同样需要将 `preserveFocus` 设为 `true`：
```typescript
if (!group1 || !isSourceTab(group1.activeTab, uri)) {
  await vscode.window.showTextDocument(uri, {
    viewColumn: vscode.ViewColumn.One,
    preserveFocus: true // 👈 保持焦点，防止编辑器强夺资源管理器的焦点
  });
}
```

### 3. 清理收尾时的聚焦逻辑
在 `arrangeMarkdownLayout` 的末尾，之前有一步“恢复键盘焦点到 Group 1”的逻辑：
```typescript
// 调整前：
const finalGroup1 = vscode.window.tabGroups.all.find(g => g.viewColumn === vscode.ViewColumn.One);
if (finalGroup1 && !isSourceTab(finalGroup1.activeTab, uri)) {
  await vscode.window.showTextDocument(uri, {
    viewColumn: vscode.ViewColumn.One,
    preserveFocus: false
  });
}
```
* **优化**：
  由于我们在前两步（打开源文件、打开预览）都已经严格使用了 `preserveFocus: true`，此时整个布局重组已经在后台静默完成，原始的焦点（如资源管理器）被完好地保留着。
  因此，末尾的这步重新 show 并强行夺走焦点的逻辑是**多余且有害**的，可以直接将其移除，或者确保也使用 `preserveFocus: true`。为了防微杜渐，我们将其中的 `preserveFocus` 改为 `true` 或直接移除（因为在第一步已经确保打开了该文件）。

## 预估变更代码 (src/markdownDualPane.ts)

修改 `arrangeMarkdownLayout` 方法中的参数设置：

```typescript
async function arrangeMarkdownLayout(uri: vscode.Uri): Promise<void> {
  if (isLayoutAlreadyCorrect(uri)) {
    return;
  }

  log(`Arranging dual pane layout for: ${uri.fsPath || uri.toString()}`);

  // Close existing preview for this file if it is in the wrong group.
  const existingPreview = findPreviewTab(uri);
  if (existingPreview && existingPreview.group.viewColumn !== vscode.ViewColumn.Two) {
    await vscode.window.tabGroups.close(existingPreview.tab);
  }

  const groups = vscode.window.tabGroups.all;
  const group1 = groups.find(g => g.viewColumn === vscode.ViewColumn.One);

  // 1. 使用 preserveFocus: true 打开源文件/Diff
  if (!group1 || !isSourceTab(group1.activeTab, uri)) {
    await vscode.window.showTextDocument(uri, {
      viewColumn: vscode.ViewColumn.One,
      preserveFocus: true // 👈 保持原有焦点
    });
  }

  // 2. 使用 preserveFocus: true 打开 Markdown 预览
  if (!findPreviewInGroup(uri, vscode.ViewColumn.Two)) {
    await vscode.commands.executeCommand(
      'vscode.openWith',
      uri,
      markdownPreviewViewType,
      { 
        viewColumn: vscode.ViewColumn.Two, 
        preview: true,
        preserveFocus: true // 👈 保持原有焦点
      }
    );
  }

  // 3. 移除多余组
  await closeExtraGroups();
}
```

## 验证计划

### 1. 手动测试场景
- **资源管理器键盘导航测试**：
  在 Explorer 中选中一个 `.md` 文件，然后使用方向键（`↓` 或 `↑`）切换到其他 `.md` 文件。
  - **预期表现**：每当切换到一个 `.md` 文件，双栏布局和预览都在右侧自动更新，但**焦点仍然完美留在 Explorer 中**，用户可以一直用方向键继续上下浏览，且可以直接按 `Delete` 删除当前选中的文件。
- **Source Control 键盘导航测试**：
  在 SCM Changes 面板中选中一个 `.md` 变更，用方向键上下浏览。
  - **预期表现**：焦点保持在 SCM 面板，双栏和预览自动流转。
- **编辑器直接编辑测试**：
  在编辑器内双击打开一个 `.md`，此时焦点在编辑器里。输入字符，验证自动分栏拉起预览后，焦点依然留在当前的输入光标处，不会被打断。
