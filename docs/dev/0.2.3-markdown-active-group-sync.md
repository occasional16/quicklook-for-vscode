# 0.2.3. Markdown 双面板活跃编辑器组同步优化

## 目标

解决“Markdown 智能双面板锁定”功能在频繁使用下的两个严重体验问题：
1. **双栏重组时的视觉闪烁**：点击 `.md` 文件后，文件常常先在右侧（Group 2）被打开，然后闪烁移动到左侧（Group 1）。
2. **SCM 面板 Diff 视图消失 Bug**：在版本控制（Source Control）面板中双击或单击 `.md` 变更文件后，Diff 视图在短暂闪烁后被彻底关闭并替换为普通编辑器，无法查看变更对比。

---

## 问题分析与根因

### 1. VS Code 的默认打开逻辑
当用户在资源管理器（Explorer）或 SCM 变更面板中点击一个文件时，VS Code 总是将文件打开在**当前处于活跃状态的编辑器组（Active Editor Group）**。

### 2. 活跃编辑器组在 Group 2 的“漂移”
当在右侧 Group 2 开启 Markdown 预览后：
1. 调用 `vscode.commands.executeCommand('vscode.openWith', ..., { viewColumn: Two, preserveFocus: true })` 在右侧 Group 2 渲染预览 Webview。
2. 虽然由于 `preserveFocus: true`，键盘输入焦点依然保持在 Explorer / SCM 面板中，但 **VS Code 内部的“活跃编辑器组（Active Editor Group）”已经被隐式切换到了 Group 2**（因为 Group 2 刚刚打开了新 tab 并获得了焦点高亮）。

### 3. 下一次点击的行为链条（若 Group 2 未锁定）
当下一次用户在 Explorer/SCM 中点击下一个 `.md` 文件时：
1. 因为当前的“活跃编辑器组”是 Group 2，VS Code 顺理成章地**直接在右侧 Group 2 中打开了该文件**（文本编辑器模式）。
2. 我们的 `onDidChangeActiveTextEditor` 监听器被触发，检测到活动编辑器出现在 Group 2。
3. 布局逻辑运行：
   - 发现左侧 Group 1 没有该文件，于是调用 `showTextDocument` 在左侧 Group 1 重新打开该文件。
   - 调用 `openWith` 在右侧 Group 2 重新拉起预览，替换掉刚才误在 Group 2 打开的文本编辑器。
4. **这就导致了闪烁**：文件先在右侧闪现文本编辑器，再在左侧重新加载打开，右侧替换为预览。

---

## 优化方案设计

为了彻底解决此问题，我们探索了两种设计思路：

### 方案 A：锁定 Group 2 结合动态解锁（已弃用）
通过 `workbench.action.lockEditorGroup` 锁定 Group 2。这样 VS Code 在打开文件时会强制跳过 Group 2，直接在 Group 1 打开。
* **局限性**：锁定 Group 2 会导致用户无法直接在 Group 2 中通过侧边栏点击打开其他类型的文件（如 `.js`, `.css`）。如果使用动态解锁（当 Group 2 激活时自动解锁），一旦 Group 2 处于活跃且解锁状态，再次点击 `.md` 文件时仍会先在右侧闪现。
* **结论**：在 VS Code API 限制下，无法做到“完美防闪烁锁定”与“在右侧自由点击打开新文件”的自动兼顾。如果提供配置项由用户权衡，会增加配置复杂度。

### 方案 B：强制激活 Group 1 + 侧边栏焦点还原（最终采纳的柔性方案）
本扩展最终决定**不锁定 Group 2**，保持编辑器组的完全柔性，同时通过精确的焦点管理将闪烁降到最低：

1. **强制激活 Group 1**：在 `arrangeMarkdownLayout` 的末尾，我们通过 `preserveFocus: false` 显式聚焦左侧 Group 1。VS Code 在收到 `preserveFocus: false` 时，会切实地把 Group 1 设为活跃编辑器组（Active Editor Group）。
2. **侧边栏焦点还原**：
   - 如果用户是通过侧边栏**单点击**（预览模式，即 `tab.isPreview` 为 `true`）打开的 Markdown 文件，我们必须将焦点还给侧边栏，以便用户继续使用键盘上下键浏览。
   - 在强制激活 Group 1 后，如果检测到当前 Tab 为预览 Tab，立即调用 `workbench.action.focusSideBar` 将键盘焦点归还给侧边栏。
   - 如果是**双击或回车**打开（非预览 Tab），则保留焦点在编辑器中。

### 详细的恢复逻辑代码实现

在 `arrangeMarkdownLayout` 末尾增加以下步骤：

```typescript
  // Restore Group 1 as the active editor group.
  const finalGroups = vscode.window.tabGroups.all;
  const finalGroup1 = finalGroups.find(g => g.viewColumn === vscode.ViewColumn.One);
  if (finalGroup1 && finalGroup1.activeTab) {
    const tab = finalGroup1.activeTab;
    const isPreview = tab.isPreview;

    if (tab.input instanceof vscode.TabInputTextDiff) {
      await vscode.commands.executeCommand(
        'vscode.diff',
        tab.input.original,
        tab.input.modified,
        tab.label,
        {
          viewColumn: vscode.ViewColumn.One,
          preserveFocus: false // 👈 强制聚焦以将活跃组拉回 Group 1
        }
      );
    } else {
      await vscode.window.showTextDocument(uri, {
        viewColumn: vscode.ViewColumn.One,
        preserveFocus: false // 👈 强制聚焦以将活跃组拉回 Group 1
      });
    }

    // 如果是单点击（预览模式），则将焦点还给侧边栏
    if (isPreview) {
      await vscode.commands.executeCommand('workbench.action.focusSideBar');
    }
  }
```

## 预期效果与限制

1. **日常连续浏览零闪烁**：在 Explorer / SCM 中连续单点击浏览不同的 `.md` 文件时，由于每次排列完后 Group 1 都会被重置为活跃组，文件会直接在左侧 Group 1 中打开，**绝对无闪烁**。
2. **完美保留 Diff**：在 SCM 变更中双击 `.md`，它在左侧 Group 1 以 Diff 视图正常打开，右侧 Group 2 正常拉起预览，且 Diff 视图完好无损。
3. **日常多栏兼容性**：用户可以像原生 VS Code 一样，自由在右侧 Group 2 中以任何方式（单击、双击、侧边打开）打开并编辑任意非 Markdown 文件，没有任何强制锁定干预。
4. **单次闪烁限制**：仅当用户手动去右侧 Group 2 里点击了内容或预览标签后（此时活跃组变为 Group 2），下一次在侧边栏点击 `.md` 文件时，会有一次正常的“在右侧闪现并移回左侧”，随后活跃组被重置回 Group 1，后续点击恢复无闪烁。这做到了当前 VS Code 限制下的最优解。
