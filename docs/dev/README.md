# 开发工作文档

`docs/dev/` 用于保存本项目临时、可审阅的方案、诊断、决策和执行记录。这里的文件不是产品文档，也不自动成为长期项目规范；需要长期保留的结论应在用户批准后整理到合适的正式文档中。

## 使用边界

- 仅在用户明确要求或同意后创建工作文档。
- 方案获批不等于已授权执行；实施、提交、推送、移动或删除仍以用户当次要求为准。
- 不在工作文档中保存密钥、凭据或其他不应进入 Git 的敏感信息。

## 命名与语言

- 文件统一放在 `docs/dev/`，命名格式为 `<major>.<minor>-<sequence>-<topic>.<ext>`。
- `<major>.<minor>` 表示文档所属的产品版本线。例如，`0.2.x` 版本线使用 `0.2`。
- `<sequence>` 使用两位顺序编号，从 `01` 开始，按创建顺序递增；进入新的版本线后重新从 `01` 编号。创建前应检查现有文件并使用下一个编号。
- 示例：`0.2-01-topic.md`、`0.2-02-topic.md`、`0.3-01-topic.md`。
- `topic` 使用简短、清晰的英文 kebab-case 名称；本 `README.md` 不参与编号。
- 正文默认使用中文；代码、命令、文件名和专有名词保留英文。用户另有要求时，以用户要求为准。

## Markdown 模板

```markdown
# 标题

| 字段 | 内容 |
| --- | --- |
| 状态 | Draft / Active / Completed / Superseded |
| 日期 | YYYY-MM-DD |
| 目标 | 本文要解决的问题或形成的决定 |
```

正文按任务需要组织，不强制设置固定章节。状态变更、归档或删除均需用户确认。
